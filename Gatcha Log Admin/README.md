# Gatcha Log Admin

이 저장소가 발행하는 운영 JSON 의 편집 콘솔. 빌드 없음 · 의존 없음 — 정적 파일 8개가 전부다.

배포: <https://gatcha-log.web.app>

## 다루는 리소스

| 리소스 | 정본 파일 | 라이브 문서 | 앱 |
|---|---|---|---|
| 호요랜드 | `config/hoyoland_v2.json` | `config/hoyolandV2` | `HoyolandApi` (27.51.0 이상) |
| ZZZ 배너 | `config/zzz_banners.json` | `config/zzzBanners` | `ZzzBannerApi` |

| 앱 배포 | `version.json` (루트) | **없음** (아래 참고) | `UpdateChecker` |

좌측 상단 스위처로 전환한다. 리소스마다 초안 · 검증 · 라이브 상태가 따로 붙는다.

> **옛 호요랜드 자리는 따로 편집하지 않는다 — 반영할 때 같이 맞춰진다.**
> `config/hoyoland.json` · 라이브 `config/hoyoland` 는 27.50.x 이하가 읽는다. 그 버전들은
> 빈 날짜(일정 미정)를 '개막 전' 으로 읽어 D-0 배너를 세운다(2026-10-06). 그래서 어드민이
> 「라이브 반영」 때 판을 보고 가른다:
>
> | 반영하는 판 | 새 문서 `hoyolandV2` | 옛 문서 `hoyoland` | 구버전이 보는 것 |
> |---|---|---|---|
> | 시작일 · 종료일이 잡혀 있다 | 쓴다 | **같은 값을 같이 쓴다** | 새 버전과 같은 정보 |
> | 일정 미정(날짜 빈칸) | 쓴다 | 그대로 둔다 | 직전 회차 · 종료 |
>
> 매년 회차를 넘길 때 따로 할 일은 없다 — 폐막 뒤 다음 회차를 일정 미정으로 반영하면 옛 문서는
> 직전 회차로 남고, 날짜가 발표돼 반영하는 순간 두 문서가 다시 같아진다. 정본 파일도 같은 규칙이다:
> 날짜가 잡힌 판을 내보냈으면 같은 내용을 `config/hoyoland.json` 에도 덮어쓴다(내보내기가 알려 준다).
>
> 구버전의 한계 하나: 참여 게임 · 입장 조 · 배치도가 **비어 있으면** 구버전은 앱에 번들된 2026 값을
> 대신 그린다. 새 회차 날짜를 올릴 때 이 셋이 아직 비어 있으면 구버전 화면에 2026 것이 잠시 보인다.

## 호요랜드 회차 — 26년 / 27년 / 행사 추가

호요랜드 화면 본문 위에 **회차 탭**이 선다(시안 「회차 탭 · 안 A」). 탭 하나가 회차 한 벌이고,
탭 아래 보조 한 줄이 그 회차의 상태다.

| 상태 | 뜻 | 문서(Firestore `config/…`) | 정본 |
|---|---|---|---|
| 앱에 게시 중 | 앱이 읽는 회차. 한 번에 하나 | `hoyolandV2`(+ 날짜가 잡히면 `hoyoland`) | `config/hoyoland_v2.json` |
| 보관 | 게시된 적이 있는 지난 회차 | `hoyolandEdition{연도}` | `config/hoyoland/editions/{연도}.json` |
| 게시 전 | 「행사 추가」로 만든 다음 회차 | `hoyolandEdition{연도}` | `config/hoyoland/editions/{연도}.json` |

회차 목록은 `hoyolandEditions`(정본 `config/hoyoland/editions.json`)에 있다 —
`{ published, editions, archived }`. 못 읽으면 앱 내장값이 가리키는 두 회차(`HOYOLAND_BUNDLED`)로 뜬다.

- **앱은 바뀐 것이 없다.** 앱이 읽는 자리는 그대로 `hoyolandV2` 하나이고, 회차 문서 · 목록은 어드민만 읽는다.
  게시 중인 회차의 편집 · 반영 · 이력도 예전과 같다.
- **보관 · 게시 전 회차는 「저장」만 한다.** 상단바의 「라이브 반영」이 「저장」으로 바뀌고, 제 회차 문서에 쓴다
  (GitHub 가 연결돼 있으면 정본 파일도 같이 커밋). 앱에는 나가지 않는다.
- **git 에서 고친 회차는 「반영 · 이력」 ▸ 「정본 파일」 ▸ `정본 불러오기` → 「저장」으로 올린다.** 상단바 `불러오기` 는
  회차 문서를 먼저 읽어 옛 값이 다시 온다(2024 · 2025 를 git 으로 채운 뒤 생긴 길, 2026-10-06).
- **「행사 추가」는 회차를 만들기만 한다.** 행사명 끝의 연도가 회차 ID 이자 탭 이름이다(「호요랜드 2028」 → `28년`).
  새 회차는 일정 미정으로 시작하고, 「지난 행사」는 게시 중인 회차의 요약을 맨 앞에 얹어 물려받는다.
- **회차가 넘어가는 길은 「이 회차를 앱에 게시」 하나다**(게시 전 회차의 「반영 · 이력」). 한 배치로
  ① `hoyolandV2` 를 새 회차로 갈고 ② 게시 중이던 회차를 **지금 앱이 보는 값 그대로** 제 회차 문서로 옮기고
  ③ 목록의 게시 중 회차를 바꾼다. 구버전 문서는 새 회차에 날짜가 잡혀 있을 때만 같이 쓴다(위 표와 같은 규칙).
  정본은 그 뒤를 따른다 — 새 회차는 `hoyoland_v2.json` 의 주석만 물려받고, 직전 회차는 `config/hoyoland/editions/` 로 간다.
- **26년 보관본.** 회차를 나누기 전의 2026 데이터는 구버전 문서(`hoyoland` · `config/hoyoland.json`)에 통째로 있었다.
  `config/hoyoland/editions/2026.json` 이 그 보관본이다. 26년 탭은 회차 문서 → 이 정본 → 구버전 문서 순으로 읽고,
  날짜가 잡힌 판을 반영해 구버전 문서를 덮게 될 때는 거기 남은 회차를 보관 문서로 먼저 옮겨 싣는다.

### 저장소의 파일 자리

| 자리 | 무엇 | 누가 읽나 |
|---|---|---|
| `config/hoyoland_v2.json` | 앱에 게시 중인 회차의 정본 | 앱 27.51.0 이상 — **경로 고정** |
| `config/hoyoland.json` | 구버전용 정본 | 앱 27.50.x 이하 — **경로 고정** |
| `config/hoyoland/editions.json` | 회차 목록 | 어드민 |
| `config/hoyoland/editions/{연도}.json` | 보관 · 게시 전 회차 | 어드민 |
| `config/goods/{연도}/` · `config/food/{연도}/` | 그 회차의 굿즈 · 푸드 사진 | 앱(JSON 안의 경로로) · 어드민 |
| `config/partner/` | 파트너사 로고 — 회차와 무관 | 앱 |

앱이 읽는 두 파일은 깔린 앱에 주소가 박혀 있어 옮기지 못한다. 어드민만 읽는 것은 `config/hoyoland/` 아래에 모은다.

사진은 **회차 폴더**에 둔다. 「올리기」는 지금 보고 있는 회차의 폴더에 올리고 번호도 그 안에서 잇는다.
2026 사진은 처음에 `config/goods/` · `config/food/` 바로 아래에 있다가 회차 폴더로 옮겼다(2026-10-06,
`ASSET_MOVED_YEARS`). 그 회차 문서에 남은 옛 경로(`goods/hsr-036.webp`)는 어드민이 읽을 때 새 경로로 고쳐 읽고,
26년을 저장할 때 구버전 문서(`config/hoyoland`)의 경로도 같이 고친다 — 경로만 바뀌고 내용은 그대로다.

## 데이터 흐름

```
어드민 ──라이브 반영──> Firestore config/{doc} ─┐
                                                ├──> 앱
어드민 ──정본 내보내기──> git *.json ───────────┘
                                                └──> 번들 기본값
```

앱은 **라이브 → 정본 → 번들** 순으로 내려온다(`Gatcha Log Shared/.../api/LiveConfig.kt`).
라이브는 커밋 없이 즉시 반영되는 현장 대응용이고, 정본은 git 에 남는 이력이자 최종 폴백이다.
둘이 어긋나면 앱은 라이브를 믿는다 — **대응이 끝나면 정본도 갱신해 커밋한다.**

앞 단계가 깨진 JSON 이어도 다음 단계로 내려간다. 어드민이 잘못 쓴 문서 하나로 화면이 비지 않는다.

### version.json 에 라이브가 없는 이유

`minVersionCode` 는 강제 업데이트를 거는 값이다. 오타 하나로 전 사용자를 존재하지 않는 버전으로
밀어 버릴 수 있고, 되돌리는 동안 앱은 잠긴다. 이 경로만은 git 리뷰와 이력을 거치게 뒀다.
대신 검증을 세게 넣었다 — `versionName`↔`versionCode` 규칙, `minVersionCode > versionCode`
소프트 브릭, sha256 64자리.

## 앱 공지

홈 맨 위에 서는 배너다. 점검 · 장애 · 행사 안내처럼 **앱을 업데이트하지 않고** 알려야 할 때 쓴다.
모양은 HoYoLAB 토큰 만료 배너와 같고(화면 폭 띠 · 아이콘 · 제목 · 내용 · 버튼), 종류에 따라 색만 바뀐다.

| 칸 | 값 | 비우면 |
|---|---|---|
| 제목 | 한 줄 | **그 공지를 버린다** |
| 내용 | 한두 줄 | 제목만 뜬다 |
| 종류 | 안내(강조색) · 주의(경고색) · 긴급(급한 경고색) | 안내 |
| 대상 | 모두 · Android · iOS | 모두 |
| 시작 · 종료 | KST `yyyy-MM-dd HH:mm` | 지금부터 · 내릴 때까지 |
| 주소 · 버튼 글자 | 주소가 있어야 버튼이 붙는다 | 버튼 없음 · 글자는 「자세히」 |

- 종료가 지난 공지는 앱이 스스로 내린다 — 지우지 않아도 된다. 앱을 켜 둔 채 종료 시각을 넘겨도 내려간다.
- 시작 · 종료를 **적었는데 앱이 못 읽으면 그 공지는 안 뜬다**(2월 30일 · 24시 · "내일까지"). 기간을 모르는
  공지를 무기한 띄우느니 안 띄우는 쪽을 골랐다. 브라우저의 `Date.parse` 는 2월 30일을 3월 2일로 넘겨 받아 주므로
  검증은 그것을 쓰지 않고 달력 날짜인지 따로 본다(`isRealKst`).
- 앱은 한 번 받은 공지를 다음 조회가 실패해도 붙들고 있는다. 점검 공지가 지하철에서 사라지면 점검이 끝난 것으로 읽힌다.
- 27.51.0 미만 앱은 이 문서를 읽지 않는다 — 구버전에는 공지가 가지 않는다.

## 리딤코드 보정

코드 목록의 본체는 외부 수집 API(hoyo-codes)다. 어드민은 **덧대는 것**만 다룬다.

- **직접 넣는 코드** — 수집 목록 앞에 붙는다. 수집에 같은 코드가 있으면 여기 적은 보상 · 강조가 이긴다.
  보상은 **적은 그대로** 보인다(수집 쪽과 달리 한국어화하지 않는다). 만료를 넣으면 그 시각에 앱이 뺀다.
- **숨길 코드** — 수집 목록에 있어도 **모든 사용자에게서** 빠진다. 수집 API 가 수량이 마감된 코드를 계속
  `OK` 로 실어 보낼 때 쓴다(앱은 사용자가 직접 눌러 실패해야만 그 기기에서 가렸다).
- 수집이 실패해도 직접 넣은 코드가 있으면 그것으로 목록이 선다. 둘 다 없을 때만 「못 불러왔어요」 다.
- 둘 다 비워 두면 앱은 수집 목록을 그대로 쓴다 — 예전 동작과 같다.

게임은 `genshin` · `hsr` · `zzz` 셋이다(HoYoLAB 교환 API 가 받는 게임). 그 밖의 값은 앱이 줄째 버린다.

## 정본 커밋 · 사진 올리기 (GitHub)

**GitHub 를 한 번 연결해 두면 「라이브 반영」이 정본까지 같이 올린다.** 예전엔 반영한 뒤 「정본 내보내기」로
가서 JSON 을 확인하고 내려받아 손으로 덮어쓰고 커밋했다. 잊으면 라이브와 정본이 어긋난 채 남고, 그 사실은
라이브가 비는 날에야 드러난다. 서버가 없으므로 브라우저가 GitHub API 를 직접 부른다(`github.js`).

- 순서는 **라이브 → 정본**이다. 정본 커밋이 실패해도 반영은 되돌리지 않는다(앱에는 이미 나갔다). 결과는
  「라이브 반영」 화면에 남고, 실패했으면 「정본 내보내기」의 버튼으로 다시 올린다.
- 연결이 없으면 반영만 되고 정본은 그대로다 — 확인 창과 「라이브 반영」 화면이 그 사실을 알린다.
- 정본 파일이 아직 없는 새 리소스는 빈 문서로 열리고, 첫 반영이 파일을 만든다.
- 「정본 내보내기」의 커밋 버튼은 반영 없이 정본만 맞출 때와 `version.json` PR 에 쓴다.

**토큰** — GitHub ▸ Settings ▸ Developer settings ▸ **Fine-grained tokens** 에서 만든다.

| 항목 | 값 |
|---|---|
| Repository access | Only select repositories → `chbk1348/Gatcha-Log` |
| Contents | Read and write |
| Pull requests | Read and write |

「정본 내보내기」의 칸에 붙여넣으면 **이 브라우저의 localStorage 에만** 저장된다. 저장소 · Firestore 로
나가지 않고, 기기마다 따로 넣어야 한다. 권한을 이 저장소 하나로 좁히는 이유는 그것이다 — 이 페이지에
XSS 가 하나 생기면 토큰이 통째로 새는데, 그때 잃는 것이 이 저장소의 쓰기뿐이어야 한다.

| 리소스 | 올리는 방식 | 이유 |
|---|---|---|
| 호요랜드 · ZZZ 배너 · 앱 공지 · 리딤코드 | 라이브 반영 때 `main` 에 같이 커밋 | 이미 라이브로 나간 값이고, 정본은 그 이력 · 폴백이다 |
| 앱 배포(`version.json`) | 「정본 내보내기」에서 가지를 만들어 **PR** | 라이브에서 뺀 것과 같은 이유 — 병합하는 한 번의 눈이 문이다 |

- 호요랜드는 날짜가 잡힌 판이면 `config/hoyoland.json`(구버전 앱용)도 **같은 커밋**에 넣는다. 파일마다
  커밋이 갈리면 둘 중 하나만 바뀐 순간이 main 에 남으므로 Git Data API 로 트리 하나 · 커밋 하나를 만든다.
- 내용이 저장소와 같으면 커밋을 만들지 않는다(트리 해시가 같다).
- 「정본 내보내기」에서 누르는 커밋은 **라이브를 바꾸지 않는다.** 앱은 라이브를 먼저 읽으므로 반영하지 않은
  편집을 커밋만 하면 앱에는 아무 변화가 없다 — 확인 창이 그 사실을 알린다.
- ⚠️ 어드민이 main 에 커밋하면 로컬 체크아웃은 뒤처진다. 작업 전에 `git pull` 한다.

**사진** — 굿즈 「사진」 · 푸드존 「메뉴 사진」 칸의 `올리기` 가 파일을 골라 `config/goods/{연도}/` · `config/food/{연도}/`
(지금 보고 있는 회차의 폴더)에 바로 커밋한다. 올리기 전에 긴 변 480px · webp 로 줄인다(작은 사진은 키우지 않는다).

- 이름은 기존 규칙을 따른다 — 게임 머리 + 그 회차 폴더 안에서 이어지는 번호(`goods/2026/gi-001` … `zzz-105`,
  `food/2026/gi-02` …). 칸에 이미 경로가 있으면 **그 이름에 덮어쓴다**(새 번호를 따면 옛 파일이 저장소에 남는다).
- 올라가는 것은 **파일뿐**이다. 경로는 칸에 채워질 뿐이라 「라이브 반영」을 해야 앱에 간다.
- 같은 이름에 덮어쓴 사진은 raw CDN 이 5분쯤 옛 것을 준다. 어드민 미리보기는 방금 올린 파일로 바로 바뀐다.

## 생김새 — GLDS

어드민도 앱과 같은 GLDS 2.0 을 따른다(저장소 루트 `CLAUDE.md` · 「GLDS 가이드」).

**화면 구성과 수치의 정본은 시안이다** — 「호요랜드 어드민 개편 시안」
<https://claude.ai/artifact/RdtTfwHXXR8EYuBdJpofGC>. 화면을 고칠 때는 시안을 먼저 고쳐 확인받고 옮긴다.
시안이 정하지 않은 것은 추측해서 채우지 않는다 — 시안을 보완하거나, 지금 모양 그대로 둔다.

| 시안에 있는 것 | 코드 |
|---|---|
| 사이드바(리소스 선택기 한 칸 · 행사/현장/기록/반영 묶음) · 상단바 상태 꼬리표 | `renderNav` · `syncDirtyBadge` |
| 대시보드 — 일정 미정 · 개막 전 | `renderHoyoDashboard` |
| 반영 · 이력(변경사항 · 반영 · 발행 이력을 한 화면으로) | `renderPublish` |
| 기본 정보 · 예매, 무대 시간표, 굿즈샵 | **아직 옮기지 않았다** — 시안 보완분 확인 대기. 지금은 예전 화면이 새 틀 안에 선다 |

**탭 분리(10/6)** — 「기본 정보 · 예매」로 합쳤던 화면을 「기본 정보」 · 「예매」 두 탭으로 다시 나눴다. 「푸드존」 · 「DIY」 탭을
새로 세웠다 — 문서 꼴은 그대로고(`programs` · `booths` 배열) 앱과 같은 기준으로 줄만 갈라 보여 준다: 제목이 「푸드」로
시작하는 프로그램은 푸드존 탭에, 게임 없이 구분이 「DIY존」인 부스는 DIY 탭에 선다.

**푸드존 탭은 음식 한 줄씩(10/6)** — 칸은 게임 · 가게 이름 · 썸네일 · 음식 이름 · 음식 설명 · 가격(원). 문서에는 예전 꼴
그대로 나간다: 게임마다 프로그램 한 건, 그 설명글에 「· 이름 — 7,000원」 줄과 들여쓴 설명 줄, `menuImages` 에 이름 → 사진
(`foodRowsFromPrograms` ↔ `foodProgramsFromRows`). 그래서 깔려 있는 앱이 그대로 읽는다. 가게 이름을 비우면 가게 줄 없이 메뉴만
나가고, **음식 이름 없이 설명만 적은 줄**은 그 가게의 안내 문구(「세트로 사면 12,000원」)로 나간다. 탭을 열어 보기만 해서는
문서가 바뀌지 않는다 — 줄을 고쳤을 때만 문서의 푸드존을 다시 만든다(`syncFood`, `markDirty` 가 부른다).

**푸드존 줄을 알아보는 기준(10/6)** — 제목이 「푸드」로 시작하거나 **메뉴 사진이 걸린 줄**이다(`isFoodProgram`, 앱
`HoyolandProgram.isFood` 와 같다). 제목만 보던 때는 제목 머리가 빠진 문서(「푸드존 — 원신」 → 「원신」) 하나로 메뉴판이 통째로
프로그램 탭과 앱의 「행사 구성」에 섰다. 그런 줄은 읽을 때 제목을 「푸드존 — 원신」으로 고쳐 두고(`normalize`), 고친 제목은
변경사항에 떠서 반영하면 문서에 남는다.

**입장 특전 탭(10/6)** — 「프로그램」 탭을 「입장 특전」 탭으로 바꿨다. 같은 `programs` 배열에서 제목이 「웰컴 키트」 ·
「입장 특전」으로 시작하는 줄만 선다(`isPerkProgram`, 앱 `HoyolandProgram.isPerk` 와 같다. 푸드가 먼저). 앱도 웰컴 키트를
「입장 특전」 섹션(예매 바로 아래)으로 갈라 세우고, 「프로그램」 섹션은 걷었다 — 무대 시간표와 같은 말을 되풀이했다.
그 밖의 줄(전시존 · 게임별 구성)은 문서에 그대로 남아 옛 빌드가 그리지만, 어드민에서는 고칠 탭이 없다. 새 줄은
「웰컴 키트 — 」를 채워 만든다 — 빈 제목은 특전으로 읽히지 않아 만들자마자 탭에서 사라진다.

**사이드바 개편(10/6, 시안 「사이드바 개편 · A」 확정)** — 메뉴를 셋으로 나눴다(`renderNav`).
위(머리 없음)는 대시보드 · 반영, 가운데는 리소스의 탭 묶음(호요랜드는 「행사 정보」 · 「현장」 — 한 줄뿐이던 「기록」을
「행사 정보」 끝으로 합쳤다), 아래 고정은 정본 내보내기 · 외부 연동(`#nav-pinned`, 예전엔 목록 끝에서 잘렸다).
묶음 머리를 누르면 접히고 이 브라우저에 기억한다(localStorage `gl-admin-nav-closed`, 막혀 있으면 이번 창 동안만).
줄마다 18 선 아이콘(`NAV_ICONS`), 꼬리는 오류(빨간 알약 · 건수) > 경고(노란 점 · 건수) > 채운 건수(회색 숫자) — 빈 「0」 은
달지 않는다. 접힌 묶음은 머리에 요약만 단다(오류 합계 · 경고 점 · 항목 수).

**「행사 정보」 6탭 개편(10/6, 시안 「행사 정보 개편」 확정)** — 한 판에 쌓던 칸을 GLDS 섹션(제목 17 · 설명 13 · 사이 띠)으로
나누고, 오른쪽에 「앱에서 보이는 모습」(앱 화면을 줄인 그림, `withPreview`)을 세웠다. 1180 미만에서는 섹션 아래로 내려간다.
- 기본 정보 · 예매 — `type: 'blocks'`(`renderBlocks`): `blocks` 하나가 섹션 하나다. `fields` 는 그대로 두어 검증 · 변경사항이 같은 이름으로 부른다.
  예매 상태는 드롭다운 대신 GLDS 탭(`segment`), 오픈 시각은 타임 피커(`hour` — 시만 고르고 분은 00 고정).
- 입장 특전 · 입장 조 · 참여 게임 — `type: 'rows'`(`renderRows`): 표 대신 줄 단위 편집(앞 꼬리표 · 칸 · 위 · 아래 · 지우기).
  참여 게임은 앱이 모르는 게임일 때만 약칭 · 색 칸이 열린다.
- 지난 행사 — 행사마다 이름 + 「항목 | 값」 줄(`renderPast`).
- 새로 계산해 보여 주는 것: 「일정」의 기간 · 지금 단계 · 발표부터 개막까지(`scheduleReadout`), 예매 「오픈 일정」의 알림 예약 시각과
  표기 비교(`ticketAlarmLine`), 「입장 조」 ↔ 예매 안내 글의 조별 시각 비교(`entryMismatch` — 다르면 검증 경고도 선다).
- 굿즈존 안내는 「기본 정보」에서 「굿즈샵」 탭 맨 위로 옮겼다(앱에서 굿즈 목록 위에 서는 글이다). 문서 키(`goodsGuide`)는 그대로 —
  변경사항은 `rootFields` 로 「굿즈샵 / 굿즈존 안내」라 부른다.

**시각은 모두 타임 피커(10/6)** — 무대 시간표 시작 · 입장 조 시각 · 예매 오픈 시각, 그리고 날짜 · 시각 칸(배너 · 공지 기간 · 리딤코드 만료)은
날짜 칸 + 타임 피커 칸 둘로 고른다(`glDateTime`). 저장되는 값의 꼴은 예전과 같다("10:00" · "2026-10-02 10:00" · 정수 시).

**화면 폭(10/6)** — 본문과 상단바는 화면 폭을 다 쓴다(좌우 20). 예전의 최대 폭(1440) 묶음은 뺐다 — 넓은 모니터에서 화면이
가운데로 쏠려 보였고, 표가 쓸 폭을 두고도 가로로 스크롤해야 했다.

**푸드존은 제목을 적지 않는다** — 게임만 고르면 앱이 읽는 제목(「푸드존 — 원신」)이 만들어진다(`foodTitle` · `foodTitleOf`).
앱은 여전히 제목으로 읽는다(「푸드」로 시작하면 푸드존, 제목 속 게임 이름으로 게임) — 문서 꼴은 그대로다. 제목 머리는
고르게 하지 않는다: 새 줄은 「푸드존」이고, 있던 줄(「푸드트럭 — …」)은 제 머리를 지킨다. 목록 화면의 열 정의에 두 변형이
생겼다: `hidden`(칸으로 세우지 않되 이름은 변경사항이 부른다 — 제목), `get` · `set`(제 키 없이 다른 값에서 읽고 쓴다 — 게임).

시안에 없는 것은 예전 그대로다: 입장 조 · 참여 게임 · 부스 체험 · 입장 특전 · 지난 행사 화면, 다른 리소스 4종의
메뉴와 화면, 다시 하기 · 파일 열기 · 정본 내보내기 · 외부 연동, 운영자 계정 · 라이브 문서 상태(「반영 · 이력」 맨 아래),
모바일의 드로어와 세로로 쌓는 표.

대시보드의 「앱에서 보이는 모습」은 앱과 **같은 규칙**으로 글자를 만든다(`hoyoPhase` · `hoyoBanner` —
`Hoyoland.kt` 의 `phase` · `statusLabel` · `periodNoYearLabel` · `venueTicketLabel`, `HoyolandTicket.kt` 의
`ticketCountdown`). 그쪽 규칙을 고치면 여기도 같이 고친다. 앱 내장 기본값 중 어드민이 아는 것은
`HOYOLAND_BUNDLED`(회차 이름 · 지난 행사 맨 앞) 하나다 — 회차를 넘기며 `HoyolandDefaults` 를 고치면 같이 고친다.

- **카드로 감싸지 않는다.** 바탕은 흰색 하나, 섹션 사이는 10 띠(`#F2F4F6`), 줄 사이는 1 헤어라인(`#EEF0F2`).
  섹션 여백은 좌우 20 · 위 22 · 아래 20. `card()` 는 이름만 예전 그대로고 화면 폭 섹션을 만든다.
  (2026-10-06 에 잠깐 구분선을 걷었다가 시안을 따르기로 하며 되돌렸다.)
- **띠는 콘텐츠 너비만큼만 긋는다 — 어드민만 다르다(2026-10-06 결정).** 앱의 띠는 화면 폭이지만 어드민은 본문 좌우 여백
  안쪽에서 끝난다. 헤어라인과 같은 폭이다. 섹션 위 배경으로 그린다(`admin.css` 의 `#main > :not(.card) > * + *`).
- **면은 뜻이 있을 때만.** 입력필드 · 버튼 · 떠 있는 것(팝오버 · 모달) · 섹션 속 작은 판(도구 줄 · 코드 블록 ·
  앱 시트 미리보기) · 객체 하나를 담는 타일(사진 미리보기).
- **컴포넌트는 GLDS 값.** 버튼 `.btn`(Neutral S) · `.btn-primary` · `.btn-secondary` · `.btn-danger` ·
  `.btn-sm`(XS) · `.btn-m`(M), 입력필드(채운 면 `#F5F8F8` · 포커스는 흰 면 + 안쪽 1.5 강조색 · 폼은 M 48, 표는 S 38),
  칩(`.gl-chips`), 스위치(50×30), 확인 모달(GlgDialog — 반경 24 · 버튼 1 : 1.4).
- **글자 하한.** 섹션 제목 17 Bold · 본문 14 · 값 15 Bold · 보조 12. 지표는 타일 면 없이 「값 / 라벨」.
- 강조색은 앱 기본값인 틸(`#1B8E99`)이다. 값은 `admin.css` 의 `:root` 토큰 한 곳에 모여 있다.

가이드에 없는 부품 — 체크박스 · 숫자 스테퍼 · 색 고르기 · 토스트 · 코드 블록 · 표. 어드민에만 있는 것이라
모양을 새로 정하지 않고 GLDS 토큰(색 · 반경 · 글자 크기)만 입혔다. 버튼 hover 도 가이드에 없어(앱은 터치다)
누름보다 옅은 한 단만 준다.

## 발행 이력 · 되돌리기

라이브 문서는 반영할 때마다 통째로 덮어써서 직전 값이 사라진다. 그래서 반영과 **같은 배치**로
`config/{doc}/history/{버전}` 에 한 벌을 남긴다(둘이 따로 나가면 "라이브는 바뀌었는데 이력엔 없는"
상태가 생긴다). 버전 ID 는 KST `20260916-143205` — 사전순이 곧 시간순이라 정렬 인덱스가 없어도 된다.

- **변경사항** — 편집본이 라이브와 무엇이 다른지 값 단위로 본다. 반영 확인 창에도 같은 요약이 뜬다.
- **발행 이력** — 최신 10판. 각 판을 지금 편집본과 비교하거나 **편집본으로 되돌린다.**
- 되돌리기는 라이브를 바로 바꾸지 않는다 — 편집본에 얹을 뿐이라, 확인하고 다시 반영해야 앱에 간다.

비교는 항목을 **자리(순서)로** 견준다. 앱 스키마에 행 ID 가 없어서 옮긴 것과 고친 것을 구별할 수
없다 — 행을 끼워 넣으면 그 아래가 전부 바뀐 것으로 보인다. 화면에도 그 사실을 적어 둔다.

이력 경로는 규칙이 따로 필요하다(서브컬렉션은 상위 문서 규칙이 내려오지 않는다). `firestore.rules`
를 같이 배포해야 이력이 쌓인다.

```bash
cd "Gatcha Log Admin" && firebase deploy --only firestore:rules,hosting
```

## 커밋이 곧 배포는 아니다

앱이 라이브를 읽으려면 **그 코드가 들어간 빌드가 기기에 설치돼 있어야** 한다. 소스에 있고
커밋돼 있어도, 구버전이 깔린 기기는 계속 raw JSON 만 본다.

또한 `google-services.json` 이 없는 빌드는 `firebaseAppExists()` 가 false 라 라이브를 건너뛴다.
**에러가 아니라 조용한 폴백**이라 알아채기 어렵다 — 연동이 안 되는 것 같으면 여기부터 본다.

## 설정 (처음 한 번)

1. **웹 앱 등록** — Firebase Console → 프로젝트 설정 → 내 앱 → 웹 앱(`</>`).
   `apiKey` · `appId` 를 `firebase-config.js` 에 채운다. 비밀이 아니라 커밋해도 되는 식별자다.
2. **운영자 uid** — 어드민에서 구글 로그인 → `라이브 반영` 화면의 `uid 복사` →
   `firestore.rules` 의 화이트리스트에 넣는다.
3. **배포**

   ```bash
   cd "Gatcha Log Admin"   # firebase.json 이 이 폴더에 있다
   firebase deploy --only firestore:rules,hosting
   ```

   ⚠️ `firebase init` 은 돌리지 않는다 — 기존 `firebase.json` 을 덮어쓴다.

| `index.html` 더블클릭 (`file://`) | X | **쓸 수 없다** — 로그인 화면을 통과하지 못한다 |

### 로그인

진입하면 로그인 화면이 먼저 선다. **우회로는 없다** — 구글 로그인을 해야 어드민 본체가 보인다.
로그아웃하면 다시 이 화면으로 돌아온다.

예외는 `firebase-config.js` 가 비어 있는 배포뿐이다. 거기서는 로그인이라는 개념 자체가 없고
라이브 반영도 꺼져 있어서 화면을 세워도 통과할 방법이 없다 — 편집 · 검증 · 정본 내보내기
전용으로 그대로 둔다. `file://` 은 값이 채워져 있어도 `cloud.js`(ESM)가 로드되지 않아
로그인을 할 수 없다. 그래서 어드민을 쓰려면 `localhost` 나 Hosting 에서 열어야 한다.
Firebase Auth 는 그 둘을 기본 승인 도메인으로 두므로 추가 설정은 없다.

### 로그인하면 값부터 맞춘다

운영자로 확정되는 순간 **모든 리소스**를 원격 값으로 맞춘다(`syncAll`). 리소스마다 앱과 같은
순서로 내려간다 — 라이브(Firestore) → 정본(raw json).

진입할 때 도는 `loadRemote()` 는 **현재 리소스 하나**를, 그것도 로그인 화면 뒤에서 받는다.
그래서 이걸 하지 않으면 두 가지가 어긋난 채 남는다.

- 안 열어 본 리소스는 빈 문서 그대로다 — 앱 배포 탭을 처음 열면 "versionName 이 비었습니다"
  같은 오류가 잔뜩 뜬다. 값이 잘못된 게 아니라 아직 받아오지 않은 것이다.
- `cloud.js`(ESM)가 늦게 오면 라이브 대신 정본으로 내려간 채로 남는다. 그 상태로 편집하면
  "지금 앱이 보는 값" 이 아니라 커밋된 값을 고치게 된다.

⚠️ **편집 중(dirty)인 초안은 덮지 않는다.** 로컬 초안은 복원된 어제 작업일 수 있다. 그대로 두고
어느 리소스를 건드리지 않았는지 알린다 — 원격 값이 필요하면 상단바 `불러오기` 로 받는다.

리소스를 전환할 때도 아직 한 번도 받아오지 않았으면 조용히 채운다(`ensureLoaded`).

### 운영자만 들어온다

로그인했다고 들어오는 게 아니다. `admin.js` 의 `OPERATOR_UIDS` 에 있는 uid 만 어드민 화면을
보고, 아니면 "접근 권한이 없습니다" 화면에서 멈춘다 — 그 화면에 자기 uid 와 복사 버튼이 있어
운영자 추가가 바로 된다.

이 목록은 **`firestore.rules` 의 `config/{doc}` 화이트리스트와 같은 값**이다. 한 곳으로 합칠 수
없어서(규칙은 JS 를 읽지 못하고, 목록을 문서에 두면 규칙 평가마다 읽기가 는다) 두 곳을 같이
고치고 둘 다 배포한다. 어긋나면 이렇게 된다:

| | 결과 |
|---|---|
| `admin.js` 에만 있음 | 들어오지만 반영이 거부된다(어드민이 알려 준다) |
| `firestore.rules` 에만 있음 | **아예 못 들어온다** ← 그래서 규칙에 넣을 때 `admin.js` 부터 넣는다 |

⚠️ **`OPERATOR_UIDS` 는 화면 접근을 막을 뿐 데이터를 지키지 않는다.** 브라우저에서 도는
코드라 우회할 수 있다. 실제 방어선은 언제나 `firestore.rules` 이고, 애초에 읽기는 공개다
(앱이 로그인 없이 읽어야 한다 — 내용도 GitHub raw 로 공개된 JSON 과 동일하다).
막는 것은 "남이 라이브를 바꾸는 것" 이지 "남이 보는 것" 이 아니다.

로그인 화면을 세울지는 `firebase-config.js` 값으로 **즉시** 판단한다. `cloud.js` 는 ESM 이라
늦게 오는데, 그걸 기다리면 대시보드가 잠깐 보였다가 덮이는 깜빡임이 생긴다.

인증 복원이 끝나기 전(`cloud.authReady === false`)의 `user: null` 은 "로그인 안 됨" 이 아니라
**"아직 모름"** 이다. 그 동안은 로그인 카드 대신 브랜드 마크와 스피너만 둔다(`settling()`) —
카드를 그리면 이미 로그인한 사람도 새로고침할 때마다 로그인 화면을 1초쯤 보게 된다.
끝내 답이 없으면(2.5초) 그때 카드를 낸다.

화면은 **상태가 실제로 달라질 때만** 다시 그린다(`gateSig`). `cloud.js` 는 부팅 · 인증 복원 ·
리다이렉트 결과 · 타임아웃마다 알리는데, 알림마다 카드를 새로 만들면 등장 애니메이션이 그만큼
재생돼 로그인 화면이 두 번 세 번 뜨는 것처럼 보인다.

## 모바일

좁은 화면에서는 세 가지가 달라진다.

- **사이드바 → 드로어.** 상단 햄버거로 열고, 항목을 고르면 닫힌다. 예전에는 사이드바를 통째로
  숨겨서(`display: none`) 리소스 전환도 섹션 이동도 못 하고 대시보드에 갇혔다.
- **표 → 카드.** 열이 많은 표는 좁은 화면에서 가로 스크롤로도 못 쓴다. 행을 카드로 쌓고 셀마다
  열 이름을 붙인다(`td[data-label]` + `::before`).
- **상단바에는 `라이브 반영` 만.** `불러오기` 는 드로어 아래로 내려가고(`.nav-only`),
  `파일 열기` · `내보내기` 는 감춘다 — 내보내기는 사이드바의 `정본 내보내기` 로 간다.

iOS 노치 대응으로 `viewport-fit=cover` 를 쓴다. 이게 없으면 사파리가 안전영역을 자기 색으로
채워 페이지 위에 띠가 얹힌 것처럼 보인다. 대신 콘텐츠가 노치에 가리지 않게 상단바 · 본문 ·
사이드바 · 로그인 화면 · 토스트에 `env(safe-area-inset-*)` 만큼 여백을 준다 — 데스크톱에서는
`env()` 가 0 이라 아무 영향이 없다. 주소창 색은 `theme-color`(`#ffffff`, 상단바와 같은 값)로 맞춘다.

입력 글자 크기는 모바일에서 16px 로 올린다. iOS 사파리가 그보다 작은 입력에 자동 확대를 걸어
키보드가 뜨며 화면이 튀기 때문이다. 드롭다운 검색창만은 `ui.css` 쪽에서 올린다 — `admin.css` 와
구체성이 같아 나중에 로드되는 `ui.css` 가 이기기 때문이다.

긴 영문 · URL · uid 는 끊을 자리가 없어 박스를 뚫는다. 좁은 화면에서만 `overflow-wrap: anywhere`
로 강제로 끊는다(`break-all` 은 "오후 3:2 / 0:00" 처럼 아무 데서나 잘라서 쓰지 않는다).
이메일 · uid · 시각처럼 값이 문자열인 타일은 `.tile.sm` 으로 작게 그리고 한 줄을 다 쓴다 —
22px 큰 숫자용 타일에 넣으면 라이브 반영 화면이 통째로 넘친다.

## 입력 위젯

브라우저 기본 위젯을 쓰지 않는다. `<select>` · checkbox · `date` · `datetime-local` ·
`number` · `window.confirm` 은 OS · 브라우저마다 생김새와 동작이 다르고 어드민 테마를 따르지 않는다.
`ui.js` 의 컴포넌트가 그 자리를 대신하고, `admin.js` 의 `inputFor` 가 스키마의 `type` 을
컴포넌트로 잇는다.

값 콜백은 둘로 나뉜다 — `onInput` 은 타이핑 중이라 초안에만 반영하고, `onChange` 는 확정이라
저장 배지(dirty)까지 찍는다. 매 글자 배지가 흔들리지 않게 하려는 구분이다.

### 글 칸은 내용만큼 자란다

폼 · 표의 글 입력은 전부 `glArea`(자라는 글 칸)다. 한 줄일 때는 한 줄 입력칸과 높이가 같고(M 48 · 표 S 38),
줄이 넘어가면 칸이 따라 늘어난다 — 손잡이도 안쪽 스크롤도 없다. 표는 칸들을 위로 맞춰 첫 줄끼리 나란히 선다.

한 줄짜리 `<input>` 은 긴 글의 뒤가 잘려 통째로 읽을 수 없었고, **줄바꿈이 든 값**(부스 설명 · 푸드 메뉴)은 화면에서
줄바꿈이 사라져 보였다 — 그 칸을 고치는 순간 저장되는 값에서도 사라진다.

- 줄바꿈을 **값으로** 받는 칸은 정해져 있다: 열 정의의 `lines: true`(설명 · 메뉴), `type: 'textarea'`(공지 · 안내),
  그리고 이미 줄바꿈이 든 값. 화면에 올리는 것만으로 값이 바뀌지 않는다.
- 나머지는 **한 문단**이다. 화면에서 접힐 뿐 Enter 를 받지 않고, 붙여넣은 글의 줄바꿈은 띄어쓰기로 바꾼다 —
  제목 · 주소 · 경로에 줄바꿈이 들어가면 앱 화면이 깨진다.
- 검색 · 채우기 · 토큰 · 날짜 · 숫자 칸은 예전 그대로 한 줄 입력칸이다.

### 설명 칸은 마크다운 에디터처럼 친다

줄바꿈을 받는 칸(설명 · 메뉴 · 공지 문구 · 굿즈존 안내 · 예매 안내 문구)은 마크다운 에디터 · 노션의 손버릇대로 친다.
칸에 마우스를 올리면 같은 안내가 뜬다(`GL_MD_HINT`).

| 치는 것 | 되는 것 |
|---|---|
| 줄 머리에 `- ` · `* ` · `+ ` | 목록 점 (붙여넣은 글의 목록 줄도) — 깊이마다 `•` → `∘` → `▪`, 노션과 같다 |
| 마크다운 목록 붙여넣기 | 깊이를 들여쓴 폭이 아니라 **포함 관계**로 센다 — 한 단을 둘 · 넷 · 탭 어느 것으로 적었든 한 단 셋으로 맞춘다(`glPasteList`) |
| `1. ` 로 시작한 줄에서 Enter | 다음 줄이 `2. ` |
| 목록 · 번호 · 들여쓴 줄에서 Enter | 다음 줄도 같은 꼴 — 빈 항목에서 Enter 면 목록 끝 |
| 표식 바로 뒤에서 Backspace | 표식을 통째로 지움(표식이 없으면 들여쓰기 한 단) |
| 목록 안에서 Tab · Shift+Tab | 한 단 들이기 · 내기 — 점 모양도 깊이를 따라 바뀐다. 들여쓴 줄은 위 항목의 부연이다 |
| ` -- ` | 줄표 ` — ` — 앱이 줄표 뒤를 값(가격 · 시각)으로 읽는다 |

- **받는 것은 앱이 그릴 줄 아는 꼴까지다.** 앱의 글 규칙(`HoyolandRichText`)은 목록 줄 · 번호 줄 · 들여쓴 부연 줄 ·
  「이름 — 값」 · 빈 줄(문단)을 안다. 굵게 · 제목 · 링크 · 인용은 모른다 — `**굵게**` 를 받아 두면 앱에 별표가 그대로 찍힌다.
  이것들을 쓰려면 앱의 글 규칙부터 늘려야 하고, 깔린 앱에서는 기호가 그대로 보인다.
- **칸에 보이는 점과 저장되는 점이 다르다.** 칸에는 깊이에 따라 `•` · `∘` · `▪` 가 보이고 값으로는 어느 것이든 가운뎃점(`·` U+00B7)이 나간다.
  앱이 「· 항목 — 값」 줄을 가운뎃점으로 알아보고(목록 · 푸드 메뉴 · 가격), 깔린 앱은 다른 글자를 목록으로 읽지 못한다.
  줄 머리(들여쓴 줄 포함)의 것만 바꾼다 — 줄 가운데의 가운뎃점(「A · B」)은 구분 기호라 그대로다.
  JSON · 변경사항에는 저장되는 글자가 보인다.
- 목록 밖에서는 Tab 이 평소처럼 다음 칸으로 넘어간다 — 표를 Tab 으로 건너다니는 길을 막지 않는다.
- 줄 가운데의 `- `(「10:00 - 11:00」)와 띄어 쓰지 않은 `--` 는 건드리지 않는다.
- 한 문단 칸(제목 · 주소 · 보상 · 비고 등)에는 적용되지 않는다. 다만 이미 줄바꿈이 든 값은 줄바꿈을 받는 칸으로 열린다.

### 순서는 끌어서 바꾼다

표 · 문자열 목록 · 날짜 묶음 · 지난 행사의 줄 끝에 손잡이(점 여섯 개)가 있다. 잡고 끌면 놓일 자리에 강조색 줄이
서고, 놓으면 그 자리로 간다(`ui.js` `glDragHandle`). 화면 끝에 가까이 가면 페이지가 따라 흐르고 Esc 는 취소다.
손잡이에 초점을 두고 ↑ ↓ 키를 누르면 한 칸씩 옮긴다. 검색으로 걸러낸 표에서는 못 옮긴다 — 보이는 이웃과
배열의 이웃이 다르다. 한 배열을 두 탭이 나눠 쓰는 표(프로그램 · 푸드존)는 이 탭의 줄끼리만 바뀐다(`reorderAt`).

### 게임은 고르는 값이다

`lineup` · `goods` · `booths` · 시간표 슬롯의 `game` 은 드롭다운(`type: 'game'`)이다.
이름이 한 글자만 어긋나도 앱은 다른 게임으로 본다 — `GameData.byNameOrNull` 이 `displayName` ·
`shortName` · `key` 로만 찾기 때문이다.

목록의 정본은 `GameData.kt` 다. 앱이 아는 6종은 약칭 · 색을 앱이 이미 알아서 `abbr` ·
`colorArgb` 를 비워 두고, 행사에만 나오는 게임(붕괴3rd · 미해결사건부 등)은 둘을 채워야 태그가
제대로 나온다. 드롭다운이 어느 쪽인지 항목마다 표시한다.

신작 · 협업 부스처럼 목록에 없는 이름은 검색창에 그대로 적어 **직접 입력**으로 넣는다.
오타를 막는 게 목적이지 값을 가두는 게 목적이 아니다. 게임이 늘면 `GameData.kt` 와
`admin.js` 의 `GAME_CATALOG` 를 같이 고친다.

### 자주 쓰는 값도 고른다

값의 집합이 사실상 정해진 칸은 `type: 'suggest'` 다 — 장소 · 예매처 · 굿즈 분류 ·
정보 항목(`facts.label`). 게임과 같은 드롭다운이지만 색 점 · 앱 지원 표시가 없다.

앱은 이 값들을 문자열로 그대로 노출할 뿐이라 목록을 지킬 의무가 없다. 매번 같은 걸 다시
타이핑하며 "아크릴" 과 "아크릴스탠드" 가 뒤섞이는 걸 막는 게 전부라, 여기도 직접 입력이 열려 있다.
목록은 `admin.js` 상단(`GOODS_CATEGORIES` · `TICKET_VENDORS` · `FACT_LABELS` ·
`VENUE_NAMES`)에 모여 있다.

반대로 행사마다 값이 새로 나오는 칸(부스 구분 · 보상 · 출연 · 배너 이름)은 자유 입력으로
뒀다. 목록이 도움이 안 되면서 선택 단계만 늘기 때문이다.

### 무대 시각은 시작만 넣는다

시간표 슬롯의 시각 칸(`type: 'hhmm'`)은 시 · 분 스테퍼다. 앱은 이 값을 **시작 시각**으로 읽고
`minutes` 로 끝을 계산해 `"13:00 ~ 14:30"` 을 만든다 — 여기에 범위를 적으면 그 계산과 겹쳐
`"13:00 ~ 14:30 ~ 15:30"` 이 된다. 그 조합은 검증이 경고로 잡는다.

`종일` · `수시` · `미정` 은 칩으로 고른다. 앱이 못 읽는 표기라 목록에만 남고 '지금/다음' 판정에서
빠지는데, 그게 의도된 동작이라 유효한 값이다(`HoyolandEvent.stageSlots`).

## 스키마를 고칠 때

정본은 **앱의 파서**다(`HoyolandApi.parse` · `ZzzBannerApi.parseOrNull` · `AppNoticeApi.parse` ·
`GiftCodeApi.parseOverrides` · `parseUpdateManifest`).
파서에 키를 추가하면 `admin.js` 의 해당 리소스 `sections` 와 `validate` 도 같이 고친다.

검증은 "파서가 실제로 버리거나 폴백하는 지점"만 짚는다 — 그 밖의 규칙을 넣으면 어드민이 앱보다
엄격해져서 거짓 경고가 된다.

주의할 파서 동작:

- 호요랜드 `lineup` · `past` 는 **빈 배열이면 번들 기본값으로 폴백**한다 → 빈 목록으로 못 내린다.
- 호요랜드 `days` · `goods` · `booths` 는 **빈 배열이 유효한 값**이다 → 통째로 내릴 수 있다.
- ZZZ `banners: []` 도 유효한 값이다("픽업 없음"). 파싱 **실패**만 정본으로 내려간다.
- ZZZ 는 `end` 가 지난 배너를 앱이 자동으로 숨긴다 → 지우지 않아도 된다.
- 굿즈 `note` 는 `" · "`(앞뒤 공백 포함)로 쪼개진다. `1인 N개 한정` 조각은 구매 제한 배지가 되고
  **N 에서 장바구니 담기 수량이 끊긴다.** `…시리즈` 로 끝나는 조각은 행사 한정 배지가 된다.
  꼴이 어긋나면 배지 · 수량 제한이 조용히 사라지므로 검증이 잡고, 굿즈 화면이 갈린 결과를 보여 준다.
- `ticket.appPackage` · `appScheme` 은 **예매 URL 이 있을 때만** 쓰인다(두 플랫폼 모두 URL 이 있어야
  "예매하기" 버튼을 세운다). 예매 상태는 `onsale` · `soldout` 도 표준 값과 똑같이 읽힌다.
- 슬롯 `time` 은 **시작 시각**이다. 끝 시각은 `minutes` 로 앱이 계산한다.
- 공지 `notices: []` · 리딤코드 `codes: []` 도 유효한 값이다("공지 없음" · "보정 없음"). 파싱 **실패**만 정본으로 내려간다.
- 공지 · 리딤코드의 시각 칸은 **적었는데 못 읽으면 그 행을 버린다**(ZZZ 배너는 0 으로 읽어 숨긴다 — 결과는 같다).
- 필수 키가 비면 **그 행만 조용히 버려진다**(`lineup.game`, `days[].ymd`, 슬롯 `title`,
  `goods.name`, `booths.title`, `past.title`, `programs.title`).
