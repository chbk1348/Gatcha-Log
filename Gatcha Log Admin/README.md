# Gatcha Log Admin

이 저장소가 발행하는 운영 JSON 의 편집 콘솔. 빌드 없음 · 의존 없음 — 정적 파일 7개가 전부다.

배포: <https://gatcha-log.web.app>

## 다루는 리소스

| 리소스 | 정본 파일 | 라이브 문서 | 앱 |
|---|---|---|---|
| 호요랜드 | `config/hoyoland.json` | `config/hoyoland` | `HoyolandApi` |
| ZZZ 배너 | `config/zzz_banners.json` | `config/zzzBanners` | `ZzzBannerApi` |
| 앱 배포 | `version.json` (루트) | **없음** (아래 참고) | `UpdateChecker` |

좌측 상단 스위처로 전환한다. 리소스마다 초안 · 검증 · 라이브 상태가 따로 붙는다.

## 데이터 흐름

```
어드민 ──라이브 반영──> Firestore config/{doc} ─┐
                                                ├──> 앱
어드민 ──정본 내보내기──> git *.json ───────────┘
                                                └──> 번들 기본값
```

앱은 **라이브 → 정본 → 번들** 순으로 내려온다(`Gatcha Log Shared/.../api/LiveConfig.kt`).
라이브는 커밋 없이 즉시 반영되는 현장 대응용이고, 정본은 git 에 남는 이력이자 최종 폴백이다.
둘이 어긋나면 앱은 라이브를 믿는다 — **대응이 끝나면 정본도 갱신해 커밋한다.**

앞 단계가 깨진 JSON 이어도 다음 단계로 내려간다. 어드민이 잘못 쓴 문서 하나로 화면이 비지 않는다.

### version.json 에 라이브가 없는 이유

`minVersionCode` 는 강제 업데이트를 거는 값이다. 오타 하나로 전 사용자를 존재하지 않는 버전으로
밀어 버릴 수 있고, 되돌리는 동안 앱은 잠긴다. 이 경로만은 git 리뷰와 이력을 거치게 뒀다.
대신 검증을 세게 넣었다 — `versionName`↔`versionCode` 규칙, `minVersionCode > versionCode`
소프트 브릭, sha256 64자리.

## 커밋이 곧 배포는 아니다

앱이 라이브를 읽으려면 **그 코드가 들어간 빌드가 기기에 설치돼 있어야** 한다. 소스에 있고
커밋돼 있어도, 구버전이 깔린 기기는 계속 raw JSON 만 본다.

또한 `google-services.json` 이 없는 빌드는 `firebaseAppExists()` 가 false 라 라이브를 건너뛴다.
**에러가 아니라 조용한 폴백**이라 알아채기 어렵다 — 연동이 안 되는 것 같으면 여기부터 본다.

## 설정 (처음 한 번)

1. **웹 앱 등록** — Firebase Console → 프로젝트 설정 → 내 앱 → 웹 앱(`</>`).
   `apiKey` · `appId` 를 `firebase-config.js` 에 채운다. 비밀이 아니라 커밋해도 되는 식별자다.
2. **운영자 uid** — 어드민에서 구글 로그인 → `라이브 반영` 화면의 `uid 복사` →
   `firestore.rules` 의 화이트리스트에 넣는다.
3. **배포**

   ```bash
   firebase deploy --only firestore:rules,hosting
   ```

   ⚠️ `firebase init` 은 돌리지 않는다 — 기존 `firebase.json` 을 덮어쓴다.

## 실행

| 방법 | 로그인 · 라이브 | 용도 |
|---|---|---|
| <https://gatcha-log.web.app> | O | 어디서나(폰 포함) |
| `python -m http.server 5173` → `localhost:5173` | O | 로컬 작업 |
| `index.html` 더블클릭 (`file://`) | X | **쓸 수 없다** — 로그인 화면을 통과하지 못한다 |

### 로그인

진입하면 로그인 화면이 먼저 선다. **우회로는 없다** — 구글 로그인을 해야 어드민 본체가 보인다.
로그아웃하면 다시 이 화면으로 돌아온다.

예외는 `firebase-config.js` 가 비어 있는 배포뿐이다. 거기서는 로그인이라는 개념 자체가 없고
라이브 반영도 꺼져 있어서 화면을 세워도 통과할 방법이 없다 — 편집 · 검증 · 정본 내보내기
전용으로 그대로 둔다. `file://` 은 값이 채워져 있어도 `cloud.js`(ESM)가 로드되지 않아
로그인을 할 수 없다. 그래서 어드민을 쓰려면 `localhost` 나 Hosting 에서 열어야 한다.
Firebase Auth 는 그 둘을 기본 승인 도메인으로 두므로 추가 설정은 없다.

### 로그인하면 값부터 맞춘다

운영자로 확정되는 순간 **모든 리소스**를 원격 값으로 맞춘다(`syncAll`). 리소스마다 앱과 같은
순서로 내려간다 — 라이브(Firestore) → 정본(raw json).

진입할 때 도는 `loadRemote()` 는 **현재 리소스 하나**를, 그것도 로그인 화면 뒤에서 받는다.
그래서 이걸 하지 않으면 두 가지가 어긋난 채 남는다.

- 안 열어 본 리소스는 빈 문서 그대로다 — 앱 배포 탭을 처음 열면 "versionName 이 비었습니다"
  같은 오류가 잔뜩 뜬다. 값이 잘못된 게 아니라 아직 받아오지 않은 것이다.
- `cloud.js`(ESM)가 늦게 오면 라이브 대신 정본으로 내려간 채로 남는다. 그 상태로 편집하면
  "지금 앱이 보는 값" 이 아니라 커밋된 값을 고치게 된다.

⚠️ **편집 중(dirty)인 초안은 덮지 않는다.** 로컬 초안은 복원된 어제 작업일 수 있다. 그대로 두고
어느 리소스를 건드리지 않았는지 알린다 — 원격 값이 필요하면 상단바 `불러오기` 로 받는다.

리소스를 전환할 때도 아직 한 번도 받아오지 않았으면 조용히 채운다(`ensureLoaded`).

### 운영자만 들어온다

로그인했다고 들어오는 게 아니다. `admin.js` 의 `OPERATOR_UIDS` 에 있는 uid 만 어드민 화면을
보고, 아니면 "접근 권한이 없습니다" 화면에서 멈춘다 — 그 화면에 자기 uid 와 복사 버튼이 있어
운영자 추가가 바로 된다.

이 목록은 **`firestore.rules` 의 `config/{doc}` 화이트리스트와 같은 값**이다. 한 곳으로 합칠 수
없어서(규칙은 JS 를 읽지 못하고, 목록을 문서에 두면 규칙 평가마다 읽기가 는다) 두 곳을 같이
고치고 둘 다 배포한다. 어긋나면 이렇게 된다:

| | 결과 |
|---|---|
| `admin.js` 에만 있음 | 들어오지만 반영이 거부된다(어드민이 알려 준다) |
| `firestore.rules` 에만 있음 | **아예 못 들어온다** ← 그래서 규칙에 넣을 때 `admin.js` 부터 넣는다 |

⚠️ **`OPERATOR_UIDS` 는 화면 접근을 막을 뿐 데이터를 지키지 않는다.** 브라우저에서 도는
코드라 우회할 수 있다. 실제 방어선은 언제나 `firestore.rules` 이고, 애초에 읽기는 공개다
(앱이 로그인 없이 읽어야 한다 — 내용도 GitHub raw 로 공개된 JSON 과 동일하다).
막는 것은 "남이 라이브를 바꾸는 것" 이지 "남이 보는 것" 이 아니다.

로그인 화면을 세울지는 `firebase-config.js` 값으로 **즉시** 판단한다. `cloud.js` 는 ESM 이라
늦게 오는데, 그걸 기다리면 대시보드가 잠깐 보였다가 덮이는 깜빡임이 생긴다.

인증 복원이 끝나기 전(`cloud.authReady === false`)의 `user: null` 은 "로그인 안 됨" 이 아니라
**"아직 모름"** 이다. 그 동안은 로그인 카드 대신 브랜드 마크와 스피너만 둔다(`settling()`) —
카드를 그리면 이미 로그인한 사람도 새로고침할 때마다 로그인 화면을 1초쯤 보게 된다.
끝내 답이 없으면(2.5초) 그때 카드를 낸다.

화면은 **상태가 실제로 달라질 때만** 다시 그린다(`gateSig`). `cloud.js` 는 부팅 · 인증 복원 ·
리다이렉트 결과 · 타임아웃마다 알리는데, 알림마다 카드를 새로 만들면 등장 애니메이션이 그만큼
재생돼 로그인 화면이 두 번 세 번 뜨는 것처럼 보인다.

## 모바일

좁은 화면에서는 세 가지가 달라진다.

- **사이드바 → 드로어.** 상단 햄버거로 열고, 항목을 고르면 닫힌다. 예전에는 사이드바를 통째로
  숨겨서(`display: none`) 리소스 전환도 섹션 이동도 못 하고 대시보드에 갇혔다.
- **표 → 카드.** 열이 많은 표는 좁은 화면에서 가로 스크롤로도 못 쓴다. 행을 카드로 쌓고 셀마다
  열 이름을 붙인다(`td[data-label]` + `::before`).
- **상단바에는 `라이브 반영` 만.** `불러오기` 는 드로어 아래로 내려가고(`.nav-only`),
  `파일 열기` · `내보내기` 는 감춘다 — 내보내기는 사이드바의 `정본 내보내기` 로 간다.

iOS 노치 대응으로 `viewport-fit=cover` 를 쓴다. 이게 없으면 사파리가 안전영역을 자기 색으로
채워 페이지 위에 띠가 얹힌 것처럼 보인다. 대신 콘텐츠가 노치에 가리지 않게 상단바 · 본문 ·
사이드바 · 로그인 화면 · 토스트에 `env(safe-area-inset-*)` 만큼 여백을 준다 — 데스크톱에서는
`env()` 가 0 이라 아무 영향이 없다. 주소창 색은 `theme-color`(`#161923`, 상단바와 같은 값)로 맞춘다.

입력 글자 크기는 모바일에서 16px 로 올린다. iOS 사파리가 그보다 작은 입력에 자동 확대를 걸어
키보드가 뜨며 화면이 튀기 때문이다. 드롭다운 검색창만은 `ui.css` 쪽에서 올린다 — `admin.css` 와
구체성이 같아 나중에 로드되는 `ui.css` 가 이기기 때문이다.

긴 영문 · URL · uid 는 끊을 자리가 없어 박스를 뚫는다. 좁은 화면에서만 `overflow-wrap: anywhere`
로 강제로 끊는다(`break-all` 은 "오후 3:2 / 0:00" 처럼 아무 데서나 잘라서 쓰지 않는다).
이메일 · uid · 시각처럼 값이 문자열인 타일은 `.tile.sm` 으로 작게 그리고 한 줄을 다 쓴다 —
22px 큰 숫자용 타일에 넣으면 라이브 반영 화면이 통째로 넘친다.

## 입력 위젯

브라우저 기본 위젯을 쓰지 않는다. `<select>` · checkbox · `date` · `datetime-local` ·
`number` · `window.confirm` 은 OS · 브라우저마다 생김새와 동작이 다르고 다크 테마를 따르지 않는다.
`ui.js` 의 컴포넌트가 그 자리를 대신하고, `admin.js` 의 `inputFor` 가 스키마의 `type` 을
컴포넌트로 잇는다.

값 콜백은 둘로 나뉜다 — `onInput` 은 타이핑 중이라 초안에만 반영하고, `onChange` 는 확정이라
저장 배지(dirty)까지 찍는다. 매 글자 배지가 흔들리지 않게 하려는 구분이다.

### 게임은 고르는 값이다

`lineup` · `goods` · `booths` · 시간표 슬롯의 `game` 은 드롭다운(`type: 'game'`)이다.
이름이 한 글자만 어긋나도 앱은 다른 게임으로 본다 — `GameData.byNameOrNull` 이 `displayName` ·
`shortName` · `key` 로만 찾기 때문이다.

목록의 정본은 `GameData.kt` 다. 앱이 아는 6종은 약칭 · 색을 앱이 이미 알아서 `abbr` ·
`colorArgb` 를 비워 두고, 행사에만 나오는 게임(붕괴3rd · 미해결사건부 등)은 둘을 채워야 태그가
제대로 나온다. 드롭다운이 어느 쪽인지 항목마다 표시한다.

신작 · 협업 부스처럼 목록에 없는 이름은 검색창에 그대로 적어 **직접 입력**으로 넣는다.
오타를 막는 게 목적이지 값을 가두는 게 목적이 아니다. 게임이 늘면 `GameData.kt` 와
`admin.js` 의 `GAME_CATALOG` 를 같이 고친다.

### 자주 쓰는 값도 고른다

값의 집합이 사실상 정해진 칸은 `type: 'suggest'` 다 — 장소 · 예매처 · 굿즈 분류 ·
정보 항목(`facts.label`). 게임과 같은 드롭다운이지만 색 점 · 앱 지원 표시가 없다.

앱은 이 값들을 문자열로 그대로 노출할 뿐이라 목록을 지킬 의무가 없다. 매번 같은 걸 다시
타이핑하며 "아크릴" 과 "아크릴스탠드" 가 뒤섞이는 걸 막는 게 전부라, 여기도 직접 입력이 열려 있다.
목록은 `admin.js` 상단(`GOODS_CATEGORIES` · `TICKET_VENDORS` · `FACT_LABELS` ·
`VENUE_NAMES`)에 모여 있다.

반대로 행사마다 값이 새로 나오는 칸(부스 구분 · 보상 · 출연 · 배너 이름)은 자유 입력으로
뒀다. 목록이 도움이 안 되면서 선택 단계만 늘기 때문이다.

### 무대 시각은 시작만 넣는다

시간표 슬롯의 시각 칸(`type: 'hhmm'`)은 시 · 분 스테퍼다. 앱은 이 값을 **시작 시각**으로 읽고
`minutes` 로 끝을 계산해 `"13:00 ~ 14:30"` 을 만든다 — 여기에 범위를 적으면 그 계산과 겹쳐
`"13:00 ~ 14:30 ~ 15:30"` 이 된다. 그 조합은 검증이 경고로 잡는다.

`종일` · `수시` · `미정` 은 칩으로 고른다. 앱이 못 읽는 표기라 목록에만 남고 '지금/다음' 판정에서
빠지는데, 그게 의도된 동작이라 유효한 값이다(`HoyolandEvent.stageSlots`).

## 스키마를 고칠 때

정본은 **앱의 파서**다(`HoyolandApi.parse` · `ZzzBannerApi.parseOrNull` · `parseUpdateManifest`).
파서에 키를 추가하면 `admin.js` 의 해당 리소스 `sections` 와 `validate` 도 같이 고친다.

검증은 "파서가 실제로 버리거나 폴백하는 지점"만 짚는다 — 그 밖의 규칙을 넣으면 어드민이 앱보다
엄격해져서 거짓 경고가 된다.

주의할 파서 동작:

- 호요랜드 `lineup` · `past` 는 **빈 배열이면 번들 기본값으로 폴백**한다 → 빈 목록으로 못 내린다.
- 호요랜드 `days` · `goods` · `booths` 는 **빈 배열이 유효한 값**이다 → 통째로 내릴 수 있다.
- ZZZ `banners: []` 도 유효한 값이다("픽업 없음"). 파싱 **실패**만 정본으로 내려간다.
- ZZZ 는 `end` 가 지난 배너를 앱이 자동으로 숨긴다 → 지우지 않아도 된다.
- 슬롯 `time` 은 **시작 시각**이다. 끝 시각은 `minutes` 로 앱이 계산한다.
- 필수 키가 비면 **그 행만 조용히 버려진다**(`lineup.game`, `days[].ymd`, 슬롯 `title`,
  `goods.name`, `booths.title`, `past.title`, `programs.title`).
